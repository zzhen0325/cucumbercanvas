# E2Eテストリスク評価

このドキュメントでは、リスクベーステスト設計に基づいて、各機能のリスク評価とテスト優先順位を定義します。

## リスク評価基準

### 影響度（Impact）

| レベル | スコア | 説明 | 例 |
|--------|--------|------|-----|
| Critical | 5 | ビジネス収益に直結、システム全体の停止 | コア機能の停止、データ損失 |
| High | 4 | 主要機能の停止、多数のユーザーに影響 | 検索機能の停止、一覧表示の不具合 |
| Medium | 3 | 一部機能の停止、限定的なユーザーに影響 | 補助機能の不具合、特定操作の失敗 |
| Low | 2 | UIの軽微な問題、回避策あり | ショートカットの不具合 |
| Trivial | 1 | 見た目の問題、影響極小 | アイコンの表示崩れ |

### 発生頻度（Likelihood）

| レベル | スコア | 説明 | 判断基準 |
|--------|--------|------|----------|
| Very High | 5 | ほぼ確実に発生 | 複雑なロジック、頻繁な変更、新規実装 |
| High | 4 | 高確率で発生 | 複数システム統合、複雑な状態管理 |
| Medium | 3 | 中程度の確率 | 既存機能の変更、標準的な実装 |
| Low | 2 | 低確率 | 安定した機能、シンプルな実装 |
| Very Low | 1 | ほぼ発生しない | 変更の少ない単純な機能 |

### リスクスコアの計算

```
リスクスコア = 影響度 × 発生頻度
```

### 優先度とテスト戦略

| スコア範囲 | 優先度 | タグ | テスト戦略 | CI/CD統合 |
|-----------|--------|------|-----------|----------|
| 20-25 | P0 (最優先) | `@smoke`, `@critical` | E2E + 統合 + 単体 | 毎PR実行必須 |
| 15-19 | P1 (高) | `@smoke`, `@regression` | E2E + 統合 | 毎PR実行推奨 |
| 8-14  | P2 (中) | `@regression` | 統合 + 単体 | リリース前実行 |
| 4-7   | P3 (低) | `@optional` | 単体テスト主体 | 必要に応じて実行 |
| 1-3   | P4 (最低) | - | 手動テスト可 | 手動テストのみ |

## テスト実行戦略

### CI/CD統合

#### PR単位での実行（毎回）
```bash
# P0, P1の重要テストのみ実行（5-7分目標）
npx playwright test --grep "@smoke"
```

#### リリース前の実行（マージ前）
```bash
# P0, P1, P2の全回帰テスト実行（10-15分目標）
npx playwright test --grep "@regression"
```

#### 定期実行（夜間）
```bash
# 全テスト実行（P0~P4）
npx playwright test
```

### テスト優先順位の見直しサイクル

- **毎スプリント**: P0/P1テストのリスクスコア見直し
- **毎リリース**: 全機能のリスク再評価
- **インシデント発生時**: 該当機能のリスクスコア再評価と優先度引き上げ
