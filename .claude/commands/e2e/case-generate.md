# E2E Test Design and Test Case Generation

E2Eテストの設計とテストケースを生成・追加します。

## 使用方法

```bash
# 初期セットアップ（ドキュメント構造作成 + 全テストケース生成）
/e2e:case-generate

# 特定機能のテストケース追加
/e2e:case-generate [機能名や説明]
```

**動作モード:**
- 引数なし: `docs/e2e/`が存在しない場合は初期セットアップ、存在する場合は全体の見直し・更新
- 引数あり: 指定された機能のテストケースを既存ドキュメントに追加

📖 **共通ルールと参照ドキュメントは `.claude/e2e-test-common.md` を参照してください。**
📖 **プロジェクト固有の設定は `.claude/e2e-config.md` を参照してください。**

## 事前確認: E2E環境の初期化（必須）

**最初に以下を確認してください：**

```bash
ls docs/e2e/
```

**`docs/e2e/` ディレクトリが存在しない場合:**
- 以下のメッセージを表示して**このコマンドを終了**してください
- 他のタスクは実行しないでください

```
❌ E2E環境が初期化されていません。

先に /e2e:init を実行してE2E環境を初期化してください。

/e2e:init
```

**ディレクトリが存在する場合のみ、以降のタスクに進んでください。**

## タスク

### 0. 【必須】ブラウザで実際の画面を確認

**⚠️ このステップをスキップしてはいけません。ブラウザを開かずにテストケースを作成することは禁止です。**

1. **開発サーバーの起動確認**
   - 開発サーバーが起動していない場合は、ユーザーに起動を依頼
   - 起動コマンドは `.claude/e2e-config.md` の「開発サーバー起動コマンド」を参照

2. **ブラウザを開いてアプリケーションを確認**
   ```
   mcp__playwright__browser_navigate: {開発サーバーURL}
   mcp__playwright__browser_snapshot: 画面全体を確認
   ```

3. **認証が必要な場合**（`.claude/e2e-config.md` で `認証が必要 | true` の場合）
   - `.auth.md` の手順に従ってログイン
   - 認証エラー時は `.claude/e2e-config.md` の「認証更新コマンド」を実行

4. **各機能の画面を実際に操作して確認**
   - 主要な画面に遷移してスナップショットを取得
   - フォーム、ボタン、リストなどの要素を確認
   - 実際の動作を確認（クリック、入力、遷移など）

**確認すべき項目**:
- 画面のレイアウトと要素
- ユーザーフロー（操作手順）
- data-testid属性の有無
- エラー表示、成功メッセージ
- API通信の挙動

### 1. テスト設計の生成・更新

- プロジェクトの要件ドキュメント（`.kiro/steering/product.md`など）を参照
- 既存の回帰テストドキュメント（存在する場合）のエッジケースを含める
- `docs/e2e/risk-assessment.md`のリスク評価を参照し、優先順位を考慮
- 共通ルール（冪等性、既存実装確認、アーキテクチャ準拠）を適用
- **出力先**: `docs/e2e/design.md`（既存の場合は追記・更新）

**リスクベーステスト設計の適用:**
- P0/P1機能を優先的にE2Eテストでカバー
- 各テストケースに適切なタグ（`@smoke`, `@critical`, `@regression`）を付与
- テストピラミッド戦略に基づき、E2Eテスト対象を厳選（10%程度）

### 2. テストケースの生成・更新

- `docs/e2e/design.md`とコードベースを基に作成
- `docs/e2e/risk-assessment.md`のリスクスコアと優先度を各テストケースに明記
- **Step 0で確認した画面情報を元に**テストケースを作成
- **出力先**: `docs/e2e/test-cases/` 配下の適切なカテゴリーファイル（既存の場合は追記・更新）

**テストケース作成時の必須事項**:
- Step 0で確認した実際の画面要素、挙動、URLをテストケースに反映
- data-testid属性の有無を明記
- API通信の有無を明記

**テストケース記述時の注意:**
- 各テストケースの冒頭に「**優先度**: P0」「**リスクスコア**: 20」を明記
- 適切なタグを付与（例: `@smoke`, `@critical`, `@regression`）
- P0/P1テストケースは詳細に記述、P3/P4は簡潔に
- カテゴリーファイル更新後、`docs/e2e/test-cases/index.md`の統計情報も更新

### 3. テストケース品質検証（完了後に実行）

テストケース生成完了後、以下の検証を必ず実施してください。

#### 3.1 自己検証チェックリスト

各テストケースについて以下を確認:

**必須項目（Must-have）**
- [ ] **Test ID**: 一意のIDが付与されているか（例: `CRUD-001`, `AUTO-TEXT-001`）
  - 形式: `[カテゴリ]-[3桁数字]`
  - 同じTest IDが重複していないか確認
- [ ] **テスト名**: 明確で具体的なテスト名があるか
  - 何をテストするのかが一目でわかる
  - 実装の詳細ではなく、ユーザー視点の動作を記述
- [ ] **目的**: テストの目的が明記されているか
  - 「〜できることを確認」の形式で記述
  - 検証対象の機能が明確
- [ ] **前提条件**: テスト実行前の状態が定義されているか
  - 認証状態、データ準備、画面状態などを明記
  - 具体的で再現可能な記述
- [ ] **テスト手順**: ステップバイステップの手順が記載されているか
  - 各ステップが明確で再現可能
  - ユーザー操作として自然な流れ
- [ ] **期待結果**: 各ステップの期待結果が明確か
  - 検証可能な具体的な基準
  - 曖昧な表現（「正常に動作する」など）を避ける
- [ ] **優先度**: P0-P4の優先度が設定されているか
  - リスク評価マトリクスに基づいた適切な優先度
  - P0/P1は必ず根拠を記載
- [ ] **タグ**: `@smoke`, `@regression` などのタグが適切か
  - P0 → `@critical`, `@smoke`, `@regression`
  - P1 → `@smoke`, `@regression`
  - P2 → `@regression`
  - P3-P4 → タグなしまたは `@optional`

**品質基準（Quality）**
- [ ] **独立性**: テストが他のテストに依存していないか
  - 単独で実行可能
  - 実行順序に依存しない
- [ ] **冪等性**: 何度実行しても同じ結果になるか
  - テストデータの準備とクリーンアップが適切
  - 固定の待機時間に依存しない
- [ ] **原子性**: 1つのテストケースが1つの機能をテストしているか
  - 複数の無関係な機能を1つのテストでテストしていない
  - 失敗時に問題箇所が明確
- [ ] **明確性**: 誰が読んでも理解できる記述か
  - 専門用語の説明
  - 曖昧な表現を避ける

**推奨項目（Should-have）**
- [ ] **リスクスコア**: 影響度×発生確率のスコアが記載されているか
- [ ] **関連テストケース**: 関連するテストへのリンクがあるか

#### 3.2 自動検証（`/e2e:qg-case`を使用）

テストケース生成完了後、以下のコマンドで準拠性を自動検証:

```bash
/e2e:qg-case
```

このコマンドは以下を自動チェック:
- Test IDの一意性
- 優先度の設定
- 必須項目の存在確認
- テストケースドキュメントの構造

詳細なギャップ分析が必要な場合:
```bash
/e2e:validate-gap-code
```

#### 3.3 検証で問題が見つかった場合

**Test IDが重複している場合:**
- 既存のTest IDを確認し、連番を調整
- カテゴリごとに001から開始

**優先度が未設定の場合:**
- `docs/e2e/risk-assessment.md`のリスク評価マトリクスを参照
- 影響度と発生確率を評価して優先度を決定

**期待結果が曖昧な場合:**
- 具体的な検証項目に書き換え
- 例: 「正常に動作する」→「一覧に作成したデータが表示される」

**テストが複雑すぎる場合:**
- 複数のテストケースに分割
- 各テストケースが1つの機能のみをテストするよう調整

#### 3.4 検証完了の確認

全てのチェック項目が✅になったら、テストケース生成が完了です。

次のステップ:
```bash
# テストコードの実装
/e2e:code-generate

# E2Eテストの実行と進捗更新
/e2e:steering
```

## 注意事項

- 実装状況やテスト結果は記載しない（`docs/e2e/progress.md`の役割）
- テストコードの実装は行わない（`/e2e:code-generate`の役割）
- **テストケース生成完了後は必ず品質検証を実施すること**
