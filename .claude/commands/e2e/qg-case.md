# E2E Test Case Quality Gate

テストケースが`case-generate.md`のルールに則っているかを検証します。

📖 **共通ルールと参照ドキュメントは `.claude/e2e-test-common.md` を参照してください。**
📖 **プロジェクト固有の設定は `.claude/e2e-config.md` を参照してください。**

## 事前確認: E2E環境の確認（必須）

**最初に以下を確認してください：**

```bash
ls docs/e2e/
```

**`docs/e2e/` ディレクトリが存在しない場合:**
- 以下のメッセージを表示して**このコマンドを終了**してください
- 他のタスクは実行しないでください

```
❌ E2E環境が初期化されていません。

先に /e2e:init を実行してE2E環境を初期化してください。

/e2e:init
```

**ディレクトリが存在する場合のみ、以降のタスクに進んでください。**

## 目的

テストケースドキュメント（`docs/e2e/test-cases/*.md`）の品質を検証し、合格/不合格を判定します。

## タスク

### 0. 【推奨】ブラウザで実際の画面と照合

テストケースの内容が実際の画面と一致しているかを確認します。

1. **開発サーバーの起動確認**
   - 開発サーバーが起動していない場合は、ユーザーに起動を依頼

2. **実際の画面で確認**
   ```
   mcp__playwright__browser_navigate: {開発サーバーURL}
   mcp__playwright__browser_snapshot: 画面要素を確認
   ```

3. **テストケースとの照合**
   - テストケースに記載されたURLが正しいか
   - テストケースに記載された操作手順が実際の画面と一致するか
   - 期待結果が実際の挙動と一致するか

### 1. テストケースファイルの検証

```bash
# テストケースファイルの一覧
ls docs/e2e/test-cases/*.md
```

各テストケースについて以下を確認:

| チェック項目 | 検証方法 | 合格基準 |
|-------------|---------|---------|
| Test ID | `\| [A-Z]+-[0-9]{3} \|` パターン | 全テストに一意のIDあり |
| テスト名 | Test IDと同じ行 | 明確で具体的な名前 |
| 目的 | `**目的**:` または `目的:` | 記載あり |
| 前提条件 | `**前提条件**:` | 記載あり |
| テスト手順 | 番号付きリスト | 1つ以上のステップ |
| 期待結果 | `**期待結果**:` | 記載あり |
| 優先度 | `P[0-4]` | 設定あり |

### 2. 違反検出パターン

```bash
# Test IDが付与されていないファイル
grep -L "| [A-Z]\+-[0-9]\{3\} |" docs/e2e/test-cases/*.md

# 優先度が設定されていないファイル
grep -L "P[0-4]" docs/e2e/test-cases/*.md

# 目的が記載されていないファイル
grep -L "目的" docs/e2e/test-cases/*.md

# 前提条件が記載されていないファイル
grep -L "前提条件" docs/e2e/test-cases/*.md

# 期待結果が記載されていないファイル
grep -L "期待結果" docs/e2e/test-cases/*.md
```

### 3. 品質ゲート判定

#### 不合格条件（1つでも該当すれば不合格）

| 不合格条件 |
|-----------|
| Test IDなしのテストケースが存在 |
| 優先度なしのテストケースが存在 |
| 目的が記載されていないテストケースが存在 |
| 期待結果が記載されていないテストケースが存在 |

#### 警告条件（合格だが改善推奨）

| 警告条件 |
|---------|
| 前提条件の記載が曖昧 |
| 期待結果が具体的でない（「正常に動作する」など） |
| テスト手順が1ステップのみ |

## 出力フォーマット

```markdown
# 🔍 E2E Test Case Quality Gate Report

**実行日時**: YYYY-MM-DD HH:mm:ss

## 判定結果

┌─────────────────────────────────────┐
│  ✅ PASSED  /  ❌ FAILED            │
└─────────────────────────────────────┘

---

## サマリー

- 検証ファイル数: X件
- 総テストケース数: Y件
- 合格: Z件
- 不合格: A件
- 警告: B件

---

## ❌ 不合格項目

| ファイル | Test ID | 違反内容 |
|---------|---------|---------|
| crud.md | - | Test IDなし（テスト「削除確認」） |
| search.md | SEARCH-003 | 優先度なし |
| bulk-edit.md | BULK-002 | 期待結果なし |

---

## ⚠️ 警告項目

| ファイル | Test ID | 警告内容 |
|---------|---------|---------|
| auto-save.md | AUTO-TEXT-002 | 前提条件が曖昧 |
| csv.md | CSV-001 | 期待結果が具体的でない |

---

## 💡 修正が必要な項目

### 即時対応（不合格項目）

1. `docs/e2e/test-cases/crud.md`
   - テスト「削除確認」にTest IDを追加（例: `CRUD-008`）

2. `docs/e2e/test-cases/search.md`
   - SEARCH-003に優先度を追加（例: `**優先度**: P2`）

---

## 🎯 次のアクション

```bash
# 違反を修正後、再度検証
/e2e:qg-case

# テストコードの品質検証
/e2e:qg-code
```
```

## 注意事項

- このコマンドは静的検証のみ（テスト実行は行いません）
- 不合格の場合、`/e2e:code-generate`の前に修正を推奨
- 警告項目は合格扱いだが、改善を推奨
